### Verified facts about the GLB
- 262 nodes, 261 meshes, **1 material** (`CineVerse_Vertex_Color_PBR`, metal 0.04, rough 0.78, doubleSided), **vertex colours only** (`COLOR_0`), no textures, no lights, no cameras.
- **~1.52 million triangles. 1.516M of them are the 100 seats** (each seat = 15,164 tris, all 100 geometrically identical). Everything else is tiny. This is the main performance problem (see §6).
- Seats ARE individual named mesh nodes: `seat_A_01` … `seat_J_10` (rows A–J = 10 rows, 01–10 = 10 per row). Map by node name. No proxies are needed for naming, but **use invisible box proxies for raycasting** (never raycast 15k-tri meshes).
- Other useful nodes: `room_floor, front_wall, back_wall, left_wall, right_wall, ceiling, acoustic_panel_{L,R}_NN, panel_trim_*, screen_outer_frame, cinema_screen_surface, screen_stage_lip, tier_platform_A..J, central_aisle_tread_*, aisle_edge_light_{L,R}_*, wall_led_*, wall_sconce_*, ceiling_light_*, speaker_tower_*, speaker_driver_*, rail_post_*`.

### COORDINATE TRAP (do not skip)
Raw vertex data is Blender Z-up, but **every mesh node carries a matrix** (Rx +90°) that converts it to glTF Y-up. After three.js loads it, world space is **glTF Y-up**:
- Screen centre ≈ `(0, 5.55, -1.255)`; screen 15.6 wide × 7.25 high (aspect 2.15).
- The audience sits at **more negative Z** (row A eye z≈-8.07 … row J eye z≈-21.57). **Seats face +Z.**
- Therefore a camera at a seat must `lookAt(screenCenter)` — the default camera forward (-Z) points AWAY from the screen. Facing +Z, the viewer's right is **-X**.
- Interior ≈ x[-11,11], y[0,11.06], z[-25.7,-0.3].
- **Seat numbering (resolved):** the GLB nodes are numbered right-to-left from the audience's view (`seat_A_01` is at x=-6, the audience's RIGHT). The public `seat_id` is mirrored (`seat_id` number = 11 - node number) so **`A01` is on the audience's LEFT (x=+6)**, matching conventional seat maps. ALWAYS map by `node_name` from the JSON (`A05` ↔ `seat_A_06`); never derive a node from the ID by string concatenation. Tests must assert the mapping for all 100 seats and that seat numbers increase left→right from the audience view in every row.
- **Never trust my numbers blindly**: at startup, load the GLB, compute each seat node's world-space Box3 with `Box3.setFromObject`, and assert it matches `seat_layout_v2.json` `bounds_gltf_y_up` within 0.01. Fail loudly in dev if not. Also assert screen centre.

### seat_layout_v2.json
Per seat: `seat_id` (e.g. `A01`), `node_name`, `node_number`, `row`, `number`, `category` (front/prime/premier), `price`, `position_gltf_y_up`, `bounds_gltf_y_up`, `eye_position_gltf_y_up`, `screen_distance`, `screen_distance_m_est`, `horizontal_offset_deg` (+ = screen centre to viewer's right), `vertical_angle_deg` (+ = looking up), `screen_h_fov_deg`, `screen_v_fov_deg`. Also `units`, `eye_model`, `categories`.

**Honesty rules (must appear in the UI as a small "How is this calculated?" popover):**
- Units are model units; `unit_to_meters_estimate = 0.43` is an ESTIMATE from seat width. Show metres as "≈".
- Eye position is a geometric estimate for a seated adult (cushion top + 0.65 m, 0.45u in front of backrest). It is NOT a measurement of a physical cinema.
- No obstruction (heads, rails, rake occlusion) is modelled. NEVER say a view is "unobstructed". Label visibility as "Geometric screen coverage". Add an `ObstructionEstimator` interface stub + TODO only.
- Expected sanity values (use as unit-test fixtures): row A centre seat h-FOV ≈ 97.7°, row E ≈ 62.6°, row J ≈ 42.0°; distances A05 ≈ 7.5u, J05 ≈ 20.4u.

## 5b. THREE MODES: Overview (orbit) · Walk (first-person, game-style) · Seated (first-person POV)

The product must feel like a first-person game, not a camera on rails. Add a **Walk mode**: the user stands in the theatre, moves with the keyboard, looks with the mouse, walks up the aisle, and sits in a seat. Mode switching is always available (toolbar + keys), and the HUD always shows the selected seats and a Continue button so booking never requires leaving first-person.

### Data (generated from the GLB; re-verify in code)
`frontend/public/models/walk_nav_v2.json` holds `walkable` surfaces (floor, 10 tier platforms, 10 central-aisle treads) and `colliders` (walls, screen frame, stage lip, speaker towers, rail posts, 100 seat boxes) as glTF Y-up AABBs, plus player parameters. At startup assert each box against the loaded GLB (world `Box3`, tolerance 0.01) and fail loudly in dev. **Never** collide or raycast against the 1.5M-triangle meshes; use these boxes.

Facts that drive the design (verified): 10 tiers, 1.5 units deep, 0.22 rise, x ±8.1. Seats are 1.28 wide, 0.98 deep, rows 1.5 apart, so only about 0.52 units between rows: **seats are solid; you walk through aisles, not between rows**. Clear central aisle is about 1.12 units wide (|x| < 0.56) with treads; side aisles run from about |x| 6.64 to the walls (±10.69). Stage lip top y≈1.56 is not climbable. Units are model units (≈0.43 m each, an estimate).

### Walk mode controls
- **↑ / W** forward, **↓ / S** back, **← / →** turn left/right (yaw), **A / D** strafe, **Shift** run, mouse = look (Pointer Lock on desktop; show "Click to look around" overlay; when pointer lock is released by Esc, show a pause overlay with "Click to resume"; never trap the user). If pointer lock is unavailable, fall back to drag-to-look. Sensitivity, invert-Y and FOV (default 70°, range 55–90°) in a settings popover, persisted.
- **Touch:** left-side virtual joystick (move), right-side drag (look), large Run toggle, tap a seat to preview it, "Sit here" button. Safe-area aware, `touch-action: none`, landscape and portrait.
- **Overview mode arrows (so the arrow keys work everywhere):** ↑/↓ dolly toward/away from the screen, ←/→ orbit left/right, + / − zoom, within the same camera clamps.
- Ignore game keys while a text field/slider is focused; release all keys on `blur`/`visibilitychange` (no stuck movement); auto-repeat safe.
- Movement must be **frame-rate independent** (use delta time, clamp delta), speeds from the JSON (walk 3.0 u/s, run 6.0 u/s), with short acceleration/deceleration smoothing. Diagonal movement is normalised. Optional subtle head bob (off by default; respects `prefers-reduced-motion`).

### Collision and ground (WalkCollision, pure TypeScript, unit-tested)
- Player = vertical capsule, radius 0.30, standing eye height from JSON (≈3.77 units above the ground; an estimate; also exposed in settings).
- Horizontal: circle-vs-AABB with sliding along surfaces (no sticking on corners, no tunnelling at high delta: sub-step the movement).
- Vertical: ground height = highest walkable surface under the player; max step-up 0.30, max step-down 0.40; smooth the eye height (critically damped) so tiers and treads feel like stairs, not teleports. Any move that would drop more than the step-down limit (tier side edges, the unreachable strip behind row J) is blocked by an invisible edge guard. No jumping, no flying, no noclip.
- **Known model limitation (document it, do not hide it):** exit doors are on the back wall at floor level, but row J sits on a platform 2.2 units higher and the aisle treads end at row J, so the back strip is not walkable to the seats. Do not spawn there. Provide a **"Go to row" teleport/auto-walk** menu and flag in `docs/3d-limitations.md` that adding rear stairs or a ramp in Blender is recommended. Do not silently alter the original geometry.
- Spawn at the bottom of the central aisle, `[0, 0, -5.5]`, looking up the aisle toward the seats (yaw facing −Z), with a first-time control hint overlay that can be dismissed and not shown again.
- Near plane 0.05 with a polygon-offset-free depth range tuned to avoid z-fighting; no clipping through seats, walls or the screen at normal approach angles (test it).

### Interaction while walking
- Centre crosshair. Aim at a seat within about 4 units (raycast against the seat proxy boxes only): highlight it and show a small label (seat ID, category, price, state). **E / Enter / click / tap** = sit (go to Seated mode). Booked and held seats can be sat in for preview, but selecting them is disabled with a clear reason.
- **Walk-to-seat:** clicking a seat from far away auto-walks along the aisle to the row entry (a scripted path that respects collisions), then side-steps into the seat and lowers to the seated eye height. Interruptible with any movement key. Respect `prefers-reduced-motion` (cut instead of glide).
- Hint bar at the bottom shows the current mode's keys (collapsible; icon-only on mobile).

### Seated mode (proper first-person seat POV)
- On entering, the camera ends at **exactly** `eye_position_gltf_y_up` for that seat (assert within 0.001 after the transition), initially looking at the screen centre.
- It is first-person head-look, not a locked screenshot: mouse/touch/gyro (optional, permission-gated on iOS) or arrow keys look around, yaw ±80° and pitch ±35° about the screen direction, damped, with a **Recentre (R)** shortcut/button. Keep the eye position fixed (no free movement while seated). Optional very subtle breathing sway, off by default.
- Hide only the seated seat's own mesh if it blocks the lens; keep all other seats so rows ahead provide natural occlusion. Geometry occlusion is real depth-buffer occlusion only; **never** claim a view is unobstructed (see honesty rules).
- **Keys (Seated):** ← → ↑ ↓ look · **Q / E** previous/next seat in the row · **Z / X** row ahead / row behind (same seat number, nearest valid) · **Enter / Space** select or deselect this seat (with toast on rejected booked/held) · **C** add to compare · **R** recentre · **Esc / Backspace / F** stand up (returns to Walk mode at the seat's aisle, not inside the row) · **O** Overview.
- Moving to another seat while seated plays a short stand, side-step, sit transition (or a quick cut under reduced motion) and always lands on the exact eye position.
- The panel and HUD keep showing distance, horizontal offset, vertical angle, screen FOV, geometric coverage, price, and the selected seats total, so booking continues without leaving first-person.

### Transitions between all three modes
Overview ↔ Walk ↔ Seated all use one camera state machine (position eased, orientation by quaternion slerp, FOV animated, interruptible, never passing through geometry; Overview→Walk descends to the nearest valid aisle spot, Walk→Overview rises and pulls back). Mode, pose, selected seats and hold state live in the Zustand store so the touch UI, keyboard, URL and the voice agent (Phase 9) all issue the same actions (`walkToSeat`, `sitAt`, `standUp`, `setMode`, `teleportToRow`).
